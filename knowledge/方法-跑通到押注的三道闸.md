# 方法-跑通到押注的三道闸

**一句话结论**：一个方向"跑通了几个案例"不等于该把它立为战略主线/北极星。升级为押注前先过三道闸——①可规模化（PoC ≠ 引擎）②命脉自主（关键环节在不在自己手里）③战功归属（上级/组织认不认是战功）。任一过不去，就降级为"带止损的 gated 实验"，别立北极星。

## 背景 / 问题
团队容易把"技术上跑通的新方向"直接当成战略重心（典型：竞观组办公环境 Benchmark，3 道成功题就想 All in）。但跑通 ≠ 可押注——热情和技术可行性会盖住三个更要命的问题。

## 结论 / 做法：押注前过三道闸
1. **可规模化闸**：几个成功案例是 PoC，不是已验证引擎。先证明——料/题源是否可持续？能否批量产出且良率可控？（呼应 [[方法-Benchmark后验难度验收]]：难度冷跑校准、产量试点量良率）
2. **命脉自主闸**：关键环节（题源、验收系统、上游数据）在不在自己手里？卡在别人系统上，再好也受制于人、随时被掐。
3. **战功归属闸**：即便做成，**上级/组织认不认它是战功**？不认 = 投产比为负，技术再漂亮也是自嗨。设方向前先 1-on-1 对齐"老板认的战功口径"，别自己猜、别埋头做完才发现不被记功。
- 过不了闸 → 降级为 **gated 实验**：小人力 + 限期（如一个季度）+ 明确止损，验证闸门后再决定加码；**不写成北极星、不 All in**。

## 反例 / 边界（何时不适用）
- 不是叫你放弃探索——是叫你**区分"实验"和"押注"**：实验可多开、必止损；押注要稀缺、要过闸。
- "战功归属"是组织现实不是犬儒：与 Robin 职能 looping"case by case 看你的 loop、当前要解决的问题"一致——方向要对齐奖励它的人。
- 若某方向明显是公司 top-down 必打的仗，战功闸自动通过，别拿它当不作为的借口。
