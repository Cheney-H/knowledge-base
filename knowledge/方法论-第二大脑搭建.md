# 第二大脑搭建方法论（CODE/PARA × 知识复利）

**一句话结论**：知识库分"项目层求全 / 复利层求通 / 记账层留痕"三层，人负责判断该记什么、哪些够通用，AI 负责总结与维护交叉引用；纯 Markdown + Git 保证工具无关，任意 Agent 可接管。

## 背景 / 问题
个人知识管理在 AI 时代的瓶颈已从"检索"转向"给 AI 提供上下文"。传统第二大脑（Forte 的 CODE/PARA）理念对，但整理全靠人的自律，多数人卡在 Capture 就放弃；卡帕西 llm-wiki（知识复利）解决了"谁来做记账苦力"——交给 AI。两者是同一哲学的互补版本：前者是蓝图，后者是自动化施工队。

## 结论 / 做法
**三层架构**：
- **项目层**（`projects/<代号>/`）：记全一个项目的一切——过程、决策、踩坑（含 `lessons.md`）。对应 Forte 的 Projects + Capture/Organize。
- **复利层**（`knowledge/`）：把跨项目反复出现或普适的经验抽象成独立页（pattern/lesson/method），用 `sources` 双链指回来源项目。对应 llm-wiki 的实体/主题页 + Forte 的"中间产物"。
- **记账层**（`log.md`）：倒序记录每次事件，可追溯。对应 llm-wiki 的复利引擎。

**运行三动作**：Ingest（随手记）/ Distill（节点深沉淀、提炼复利）/ Lint（定期体检防腐烂）。

**人机分工**：人挑什么值得记、拍板哪些够通用、提好问题；AI 总结、写文档、维护交叉引用、记账、体检。

**工具无关**：纯 Markdown + Git + schema 文件（`AGENTS.md` 主 + `CLAUDE.md` 指向它），任意 Agent（Ducc/Codex/…）读 schema 即可接管。人类侧用 Obsidian 消费双链与图谱，但只读为主、写入走 Agent+Git。

## 反例 / 边界（何时不适用）
- **范围要克制**：若只覆盖工作/项目，不必建 `raw/` 外部资料层，也不必上 PARA 全套 Areas——按需，别过度设计（YAGNI）。
- **复利层不强求**：项目专属、不通用的经验就留在项目层 `lessons.md`，不要硬往复利层塞，否则复利层被噪音淹没。
- **Obsidian 双链是方言**：飞书等镜像里 `[[...]]` 可能显示为纯文本；若强依赖多端渲染一致，需另做转换。
- **扁平化有上限**：复利层页面 >30 时再拆子目录，早拆是负担。
