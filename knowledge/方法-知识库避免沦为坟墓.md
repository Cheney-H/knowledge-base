# 方法 · 知识库如何避免沦为"知识坟墓"

> 六家 PKM 大牛实战经验的交汇点：**知识库的价值由"输出"定义，不由"藏量"定义**。破解坟墓化的统一机制——用产出倒逼输入、用加工代替囤积、复用时才做增量整理。

## 核心主线
只收集不输出 → 库越大越不敢碰 → 整体荒废。所有方法论都在对抗同一个敌人：**"存了=懂了"的错觉（收藏家谬误 / Collector's Fallacy）**。

## 六家可落地规则

- **Tiago Forte（BASB / PARA / CODE）**：按**可执行性**组织（Projects/Areas/Resources/Archive），不按学科——判据是"这条信息离哪个具体行动最近"。渐进式总结分层压缩，**只在真正复用时才多提炼一层**（成本分摊）。产出中间产物（可复用半成品），下次不从零开始。
- **Andy Matuschak（Evergreen notes）**："更好的思考"而非"更好的记笔记"。一页一个概念（**原子化**），否则无法被精准链接；按概念而非来源命名；用自己的话重写——这个"摩擦"正是思考发生处。
- **Nick Milo（LYT / MOC）**：不预建分类，等"心智挤压点"再拉 MOC（内容地图）当工作台；MOC 要**带上下文**（说明"为什么这些笔记相关"），不是纯链接列表。
- **Zettelkasten（卢曼卡片盒）**：卡片盒是"对话对象"不是存档；原子化 + 唯一 ID；**链接优先于分类**；写作驱动——目标是从盒里"长出"文章。
- **收藏家谬误（Christian Tietze）**：收集时就付出"努力型加工"（写一句"这对我意味着什么/能用在哪"），不能加工的就不存；**输出倒逼输入**（以要写/要讲/要做反推读什么）；少而精，控制库存。
- **工程师语境（ADR / 工作日志）**：ADR 架构决策记录——记"为什么 + 考虑过但放弃的选项 + 后果"，与代码同库；工作日志随手记"做了/学到/踩了什么坑"，评审晋升时变证据。learning in public 让"输出即内化"闭环。

## 对本库的落地（已对照自评）
- ✅ **三层架构** = PARA + Zettelkasten 混血；**回写铁律** = 收藏家谬误最强解药（强制加工 + 复用链接）。
- ⚠️ **原子化不足**：单页塞多概念，满 30 页拆分时按概念拆（判据见 AGENTS.md）。
- ⚠️ **缺 MOC**：现为 INDEX 目录式导航；过载时建带上下文的枢纽页。
- ⚠️ **渐进式提炼未显式分层**：首次沉淀可粗，复用时再加层。
