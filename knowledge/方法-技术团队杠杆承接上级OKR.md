# 方法-技术团队杠杆承接上级OKR

**一句话结论**：技术团队挂在战略/业务团队下，别做"任务承接"（我做的事 ≠ 上级做的事，接不上），要做"**杠杆承接 + 价值链上移**"——把技术产出折算成上级的货币（洞见/数据准确/投资/提效），KR 主语换成上级的货币、技术只当定语，并主动和上级摆一张"翻译表"把考核口径当面对齐。

## 背景 / 问题
技术团队产出的是"能力/数据/工具"，而战略/业务上级被考核的是"洞见/研究/投资/策略"。两者语言不同，中间隔着一层翻译。若技术团队只汇报技术产出（抓了多少、中台多强、工具多先进），就会"稳但承接不上、果实被下游摘、战功难归属"（见 [[lesson-基础设施型团队的战功困境]]）。

## 结论 / 做法
1. **转念：任务承接 → 杠杆承接**。不比技术强，比"技术最终折算成了多少上级记账的产出"。目标是做上级研究/业务的**引擎**，不做它的上游原料商。
2. **价值链上移**：技术别停在"供数据/供工具"，往上做一层，**直接产出上级交付物的初稿**（如用 Agent 产"洞见/策略初稿"，人精修后透传）。这样技术产出本身就是上级的货币。
3. **摆"翻译表"**：三列绑定——`技术产出（手段）→ 折算成上级战功 → 怎么考核我`，主动拿到 1-on-1 上和上级对齐。帮上级想清"这支技术队怎么用、怎么考核"，本身就是帮他明确团队重点。
4. **KR 主语换成上级货币**：写"被采用的洞见数/数据准确率/投资建议被采纳数/提效 %"，技术写在定语位。
5. **分级押注**：配合 [[方法-跑通到押注的三道闸]]——押"命脉自主 + 上级记账"的桥，守成"随大盘衰落/协作方"的线。

## 反例 / 边界
- **翻译 ≠ 甩锅**：认领了硬结果（准确率、被采纳数）就要真扛，别回头用"我们是技术团队"当挡箭牌，否则上级下次不信你。
- **价值链上移有质量风险**：初稿质量不够会砸招牌 → 先挑最可验证的场景小范围试点、评测驱动，先稳后铺。
- **天然咬合可直接认领**：若上级 OKR 里本就有数据/技术条目（如"数据严肃准确"），无需翻译，直接认领。
