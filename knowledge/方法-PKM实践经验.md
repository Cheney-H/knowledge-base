# 方法-PKM 实践经验（避开效率陷阱）

**一句话结论**：PKM 的本质是"输出决定输入"而非"输入决定输出"——先有项目/问题这个"归宿"，再据此筛选真正共鸣的信息；系统求实用不求完美，原则永远比工具重要。

## 背景 / 问题
多数人把"第二大脑"误解成"记住一切的存储库"，掉进效率陷阱：花大量时间金钱在工具上、囤积"可能有用"的信息，期待产出自动涌现。这违背了 Forte 原书的核心——action ability（可操作性）。

## 结论 / 做法

### 核心心智：输出决定输入
- 效率（productivity）词根是 produce，必须先有生产活动。先设**输出目标**，再有目的地输入。
- 费曼"12 个最想解决的问题"：脑中常备待解问题，新信息逐一比对能否帮上忙——**问题即筛选标准**。
- 每条要收集的信息都应能**找到一个归宿**（具体 project）；找不到归宿的，留在网上和留在笔记里没区别。

### 项目分两类
- **Sprint 项目**：正在集中火力冲刺完成的。
- **Slow-burn 项目**：已立项但小火慢炖、等时机成熟再冲刺的。"现在存储未来使用"只对有明确目标的 slow-burn 成立，否则就是囤积症。

### 极简法则（PCO，砍掉过度复杂的 PARA）
- **P（Project）放最前**：做笔记前先有项目盒子存在。
- **C（Capture）**：对信息有共鸣时立即捕捉、丢进对应项目。
- **(O)（Organize）加括号**：尽量少用临时收件箱——长期会懒得分类、忘记为何觉得重要。靠简化结构/减少步骤来规避。
- 两套笔记系统即可：①杂事记事本（Apple Notes 之类，别追求完美）②项目盒子笔记（唯一目的是输出）。

### 反复验证的实践经验
- **只留真正"共鸣"的**，不收集"可能重要"的（高信噪比）。
- **原子化笔记**：拆成最小可链接单元，像思维乐高，组件越小组合越灵活。
- **单一 vault 不轻易分库**：集中存放才能跨领域建立联系，顿悟多源于连接看似无关的事物。
- **用独立捕获工具**：Obsidian 不擅长快速捕获；捕获后留时间间隔再筛选导入（作者仅约 10% 进库）。
- **别让一个工具包揽一切**：理解信息如何流入流出（PKM stack），为每个任务选合适工具。
- **设备模式**：不同设备优化不同用途（手机=捕获/日记，电脑=深度工作）。
- **精选信息来源**（吉姆·罗恩三问）：我允许谁进入我的生活？对我有什么影响？这好吗（能否随时取消）？
- **系统求实用不求完美**：混乱是常态，"要让 vault 完美整洁只能永远不用它"。
- **持续创作输出**：最常见错误是只收集不创造；写作是提炼吸收信息、获得清晰认知的关键；重组现有元素同样是创造（万物皆 remix）。

## 反例 / 边界（何时不适用）
- **原则借鉴而非照搬**：效率博主推荐的工具/方法最适合他们自己（多为视频创作者），你的"盒子"未必相同——先定义自己的输出类型。
- vault 过大导致卡顿时，分库才有必要。
- 纯记杂事的记事本无需复杂化，别硬套项目框架。
